## Context

Review found: “Copy log” is a silent no-op over plain HTTP; the log pane is not keyboard-scrollable; the ready → redirect → Studio path has no browser test (so the cache loop shipped); the “starting” screenshot can be captured after the failed state; only 1280 px evidence exists; the static endpoint placeholder still has `instructions`; the startup page swallows startup/restart fetch errors; and the Engine RTF note must match the now-excluded warm-up metrics.

## Steps

1. `app/static/starting.html`:
   - “Copy log”: `navigator.clipboard` when available, else a hidden textarea + `document.execCommand('copy')`; change the label to “Copied” for 2 s and show “Copy failed” on error.
   - Log pane: `tabindex="0"`, `role="region"`, `aria-label="Engine log"`.
   - If `/api/engine/startup` returns non-2xx, show a small inline “Can’t read startup state (HTTP N) — retrying” line (don’t silently spin).
   - Restart button: surface a failed POST inline; keep the 3 s re-enable.
2. `app/static/index.html`: remove the stale `"instructions"` line from the endpoint placeholder so it matches `renderEndpoint()`.
3. `app/static/js/engine.js`: keep “Last 20 requests, warm-up excluded” (now true after M2-T16); no other data changes.
4. `tests/test_ui_assets.py`: assert the clipboard fallback, log region attributes, no `instructions` in the placeholder, and the RTF note.
5. `tests/e2e/test_startup.py`:
   - Assert `#h` is “Starting the voice engine” **before** the failure deadline, then the failed view; screenshot both 1280 and 390.
   - Add a ready-path app (normal fake engine, `startup_page=True`) where `/` initially serves the starting page, then after warm-up the page redirects and `#screen-speak` is visible; assert `/` returns `Cache-Control: no-store` via the API/test client (or a second navigation does not loop: count navigations ≤ 2).
