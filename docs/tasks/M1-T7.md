## Context

Wave-2 review proved three BLOCKERs/MAJORs in the stream path, all with deterministic repros:

1. `StreamHandle.aclose()` sets `released = True` before `await resp.aclose()`; a `CancelledError`
   during that await (a `BaseException`, not caught by `suppress(Exception)`) skips `_release()` and
   the second `aclose()` returns early → permanent slot leak.
2. `ffmpeg_stream()` calls `create_subprocess_exec` **outside** its `try/finally`, so a spawn
   failure never closes the never-started `_hold` source → engine slot + upstream response leak, and
   the error is a plain 500.
3. Unknown `voice` resolves through `store.get()` → `VoiceNotFound` (404). SPEC §6/CONTRACTS §3
   require **400 listing valid names** on `/v1/audio/speech` and `/api/speak`.

Also: `first_audio_ms` starts after response headers (understates latency); any 400/415/422 with
cfg/steps disables the knobs even if the error is unrelated; streaming treats `settings.sample_rate`
as the engine-native input rate (breaks when `SAMPLE_RATE != 48000`); transcode failures return a
plain 500.

## Steps

1. `app/engine.py`:
   - `aclose`: `released = True; try: await resp.aclose() finally: self._release()`.
   - Capture `started = time.perf_counter()` in `open_stream` **before** `_post`; pass it into the
     `chunks` closure so `first_audio_ms` includes the engine's pre-header latency.
   - cfg/steps retry: only when the upstream message mentions `cfg` or `steps`
     (`message.lower()`), never on an unrelated 4xx.
   - `restart()` timeout: `proc.kill()` then `await proc.wait()` (no zombie).
2. `app/speech.py`:
   - Add `ENGINE_SAMPLE_RATE = 48000` (module constant). Use it for the pcm passthrough comparison,
     `ffmpeg_stream` input rate, and `_wav_native` header — never `settings.sample_rate` (that is the
     output default).
   - `resolve()`: catch `VoiceNotFound` and raise `BadRequest(str(exc), param="voice",
     code="voice_not_found")` so `/v1`/`/api/speak` answer 400 with the name list; `/api/voices/{name}`
     keeps its 404 because it uses the store directly.
   - `synthesize()`: wrap `read_audio`/`transcode` in `try/except Exception` → `EngineError(...)`
     (OpenAI shape, 502) instead of a plain 500.
   - `ffmpeg_stream()`: move `_ffmpeg_args`/`create_subprocess_exec`/pipe check inside the cleanup
     scope; on any spawn/pipe error `await chunks.aclose()` and raise `EngineError`; also close
     `chunks` when the generator is never iterated (make the wrapper own the handle).
3. `tests/test_speech.py` (new — this is the missing regression protection):
   - Build a `SpeechService(store, EngineClient(fake_engine.url, concurrency=1, max_queue=0),
     settings)`; `stream()` with `response_format` `pcm`, `wav`, `mp3` → normal completion yields
     bytes with the right magic (`RIFF` for wav, non-empty for mp3) and releases the slot
     (follow-up `synth()` succeeds).
   - `stream()` with `max_queue=0` while a slot is held → `QueueFull`; dead engine URL →
     `EngineNotReady`; both raised by `await service.stream(...)`, before consuming any chunk.
   - Unknown voice → `BadRequest` (status 400, message lists `ashley-en`).
   - Monkeypatch `asyncio.create_subprocess_exec` to raise `FileNotFoundError`; `SpeechService.stream(...,
     response_format="mp3")` must raise `EngineError` and the slot must be reusable afterwards
     (`synth()` succeeds).
   - Cancel mid-stream (`agen.aclose()` after the first chunk) then a follow-up `synth()` succeeds.
   - `first_audio_ms` for input `"slow"` (fake engine sleeps 250 ms) is ≥ 100 ms.
   - `aclose` cancellation: fake response whose `aclose` raises `CancelledError`; slot is released.
4. Update `tests/test_engine.py`/`test_stream_lifecycle.py`: replace vacuous `queue_depth == 0`
   slot-leak assertions with a follow-up `synth()` (or `_sem._value`) check; keep existing tests.
5. Do not edit `app/store.py`, routers, fixtures or CONTRACTS.

### Deviations

- `ffmpeg_stream()` now takes the `StreamHandle` (instead of the `_hold` generator) and is awaited
  by `stream()`; the pump generator owns the handle and calls the idempotent `handle.aclose()` in
  its `finally`. This is the brief's "make the wrapper own the handle": a never-started generator's
  `finally` can't release the slot, so the release lives in the eager function scope (spawn) and in
  the handle's own idempotent `aclose`.
- `synthesize()` re-raises `EngineError` untouched and wraps only other exceptions, avoiding
  double-wrapping the `EngineError` that `engine.synth` already raises for undecodable audio.

### Open questions

- If a caller obtains `StreamingSpeech` and never iterates *and* never closes the chunk iterator,
  the ffmpeg process (spawned eagerly) is only reaped at GC. No current caller does this; if M1-T2's
  router can bail out between `stream()` and iteration, it should `await chunks.aclose()` there.
