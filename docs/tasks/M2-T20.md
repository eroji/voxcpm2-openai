## Context

SPEC v0.2.0 adds app-level languages. VoxCPM2 detects language from text and takes no language tag;
languages control voice tags, filters, Clone/Design choices and test phrases. Supported set comes from
`deploy/supported-languages.json` (already created, 30 entries with code/name/native). Enabled set
lives in `DATA_DIR/languages.json` (seeded en/ja/ko/zh, default en, presets seeded from
`app/static/presets.json`). The **old** simple `/api/languages` implementation was reverted; build
the spec's management API now.

## Steps

1. `app/config.py`: `supported_languages_file: Path = APP_DIR.parent / "deploy" /
   "supported-languages.json"` (env override `SUPPORTED_LANGUAGES_FILE`).
2. `deploy/Containerfile`: copy `deploy/supported-languages.json` to
   `/opt/app/deploy/supported-languages.json`; add a build check that it parses and has 30 entries.
3. `app/languages.py` — `LanguageStore(settings, voice_store)`:
   - Load supported entries (`code,name,native`), validate unique codes.
   - Seed/read `DATA_DIR/languages.json`:
     `{"default":"en","enabled":["en","ja","ko","zh"],"presets":{"en":[...],...}}`, presets seeded
     from `static/presets.json`; preserve any existing file.
   - Atomic writes (`tmp` + replace) and one `threading.RLock`.
   - `entries() -> list` default-first, each `{code,name,native,default,voices,presets,supported}`
     (`voices` = count of `voice_store.list()` with that language; `presets` = len list; `supported`
     = code in supported set).
   - `supported() -> list[{code,name,native}]`.
   - `add(code)` (400 `unsupported_language`; 409 if already enabled), `set_default(code)`,
     `presets(code)`, `set_presets(code, items)` (enabled language; ≤12; unique non-empty ids,
     non-empty label/text → 400 `invalid_presets`).
   - `remove(code, voices=None, to=None)`:
     409 `language_locked` if default or last; collect voice names using the code;
     409 `language_in_use` with the names unless `voices` is `relabel` or `delete`;
     relabel target must be enabled and ≠ code (400 `language_not_enabled`); backup first
     (`voice_store.backup("language-remove-<code>")` + copy `languages.json` to
     `backups/languages-<stamp>.json`); relabel via `voice_store.update(name, language=to)` or delete
     via `voice_store.delete`; drop the language and its presets; return `{removed, voices}`.
   - `ensure_enabled(code)` → 400 `language_not_enabled`; `is_supported(code)`.
   - Drift: enabled code missing from supported stays enabled, `supported=false`.
4. `app/routers/languages.py`: routes from SPEC §7:
   - `GET /api/languages` → `{"languages": entries}`; `GET /api/languages/supported` →
     `{"languages": [...]}`.
   - `POST /api/languages` body `{code}` → 201 entry (or 400/409).
   - `PATCH /api/languages/{code}` body `{default: true}` → entry.
   - `DELETE /api/languages/{code}` body `LanguageRemoval` (`voices: "relabel"|"delete"|None`,
     `to: str|None`) → `{"removed": code, "voices": decision}`; 404 unknown.
   - `GET /api/languages/{code}/presets` → `{"presets":[...]}`; `PUT` replaces with `PresetList`
     (`presets: list[{id,label,text}]`, max 12) → the stored list.
   - Use pydantic models; errors via `APIError` with the codes above.
5. `app/main.py`: create `app.state.languages = LanguageStore(settings, store)` in lifespan and
   include the router.
6. Voice language enforcement (use `request.app.state.languages.ensure_enabled`):
   - `studio_clone.py` clone `language`; `studio_voices.py` PATCH `language`;
     `studio_takes.py` save-as-voice `language`; `design.py` save `language`.
   - Reject unknown/disabled with 400 `language_not_enabled` before writing.
7. Tests (`tests/test_languages.py` new + updates):
   - Seed file has default/enabled/presets; GET shapes; supported has 30 with native names.
   - add supported language → empty presets; add unsupported → 400; duplicate → 409.
   - set default; remove default/last → 409; remove unused language; remove with voices no decision
     → 409 listing names; relabel → voice metadata changed + backup exists; delete → voices gone.
   - presets GET/PUT, >12 or empty fields → 400; drift (temporarily remove a code from the supported
     file via settings) → `supported:false`, still enabled.
   - Voice creation/relabel with disabled language → 400 `language_not_enabled` (clone, PATCH, design
     save, save-as-voice).
   - `test_deploy.py`: Containerfile copies the supported file; file has 30 entries.
8. Do not edit UI modules.

### Deviations

- Presets are seeded from `app/static/presets.json` (the brief) rather than `ui/presets.json`
  (SPEC §5a wording). The two files are byte-identical and `ui/` is read-only.
- `app/routers/studio_design.py` is outside `owns:`, so `DesignService.save()` builds a short-lived
  `LanguageStore(settings, store)` itself instead of reading `app.state.languages`. The file is the
  source of truth, so the check is still current.
- Enforcement tests live in `tests/test_languages.py`; the four module test files needed no change
  (every existing fixture uses `en`/`ja`, which the seed enables).
- 409 for "already enabled" uses code `language_enabled` (SPEC names no code for that case).
- `POST /api/languages` checks the supported set before the enabled set, so adding a drifted
  (enabled-but-unsupported) code answers 400 `unsupported_language`, not 409.
