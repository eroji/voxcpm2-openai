## Context

The backend now exposes the spec's language API: `GET /api/languages` (enabled, default first, with
`code,name,native,default,voices,presets,supported`), `GET /api/languages/supported`,
`POST /api/languages`, `PATCH /api/languages/{code}` (`{default:true}`),
`DELETE /api/languages/{code}` (`{voices:"relabel",to}` / `{voices:"delete"}`),
`GET|PUT /api/languages/{code}/presets`. The UI must add the sixth screen and stop using the static
`presets.json` / four-language assumptions.

## Steps

1. `index.html`: add tab `05 Languages` and renumber Engine to `06`; port the reference
   `#screen-languages` markup (table head, `#lang-rows`, `#lang-count`, add-language side panel with
   `#add-lang`/`#add-lang-btn`); include `/static/js/languages.js` after design.
2. `studio.css`: port the reference language styles (`.vs-lang-table/head/main/row/remove`, `.tag`,
   `.btn-small`, `.btn-danger`) and keep the inset select chevron.
3. `languages.js` (new, `registerScreen("languages", …)`):
   - Fetch enabled + supported; render rows default-first: name + native, code, voice count,
     `N of 6` presets / `None yet`, Default tag; actions Edit phrases / Make default / Remove.
   - Locked reasons for default/last; unsupported rows show "Not supported by the engine" instead of
     the phrase count.
   - Add picker lists supported minus enabled (name · native); Add posts `{code}`.
   - Make default PATCHes.
   - Remove: with voices show the in-place relabel/delete panel (select of enabled others,
     “Relabel and remove”, “Delete the voices too”, Cancel, the note); without voices the short
     confirm. Call DELETE with the matching body. After removal refresh all screens/state.
   - Edit phrases: inline editor rows (label + text, add/remove/reorder, Save/Cancel) using
     GET/PUT presets; empty fields block Save; max 12.
   - All server text via `textContent` (or a safe builder); errors inline.
4. `core.js`: `state.languages` (enabled entries) + `state.supportedLanguages`; `loadLanguages()`
   caches; `formatLang(code)` uses name from the enabled/supported lists with a readable fallback;
   export a helper for enabled options (default first). Re-run screen `show()` hooks after changes.
5. `speak.js`: presets from `/api/languages/{voice.language}/presets`; default selection Question;
   if empty show “No test phrases for <Language> yet” with a link to `#languages` instead of chips;
   if the selected voice's language is `supported:false`, block Generate with “This voice's language
   isn't supported by the current engine” (do not send the request).
6. `clone.js`/`design.js`: language selects from enabled languages only, default first (Clone
   English, Design Japanese if enabled else default). Design presets from the selected language's
   presets endpoint; empty list shows the same “no phrases” hint without touching typed text.
7. `voices.js`: filters list enabled languages only (default first; All first); table language names
   via `formatLang`; unsupported language shows “Not supported by the engine” in the row; language
   editor options only enabled plus the voice's own code.
8. Replace `app/static/icons/*` with the updated `ui/icons/*` binaries; keep link hrefs.
9. Tests:
   - `test_ui_assets.py`: 6 tabs/screens incl. `#screen-languages`; languages.js registered; delete
     confirm literals; presets URL shape; no `presets.json` fetch; CSS classes; icons served.
   - e2e: Languages table shows 4 rows / default; add German → 5; make default → tag moves; remove
     Japanese with voices → relabel panel, relabel to English → voices updated and Japanese gone;
     presets editor edit/save persists; design/clone selects follow enabled (+German); Speak shows
     presets for ja and the “no phrases” link when a language has none (add a language with no
     presets, e.g. German, tag a voice? simpler: design select German + empty presets hint).
   - Keep existing empty-library, presets, startup tests green.
10. Do not edit Python or `presets.json`.

### Deviations

1. Languages e2e tests run against **function-scoped** app instances (`live_langs` fixture and a
   `_serve_app` context) so add/remove/relabel mutations cannot leak into the session `live_app`
   the other tests depend on. `_seed` is now imported from `tests/e2e/conftest.py` (read-only).
2. Three existing static assertions were updated because the markup/JS they pinned moved to the
   API: `test_design_language_default_follows_reference_order` (design-lang has no static options;
   design.js prefers `ja`), `test_clone_show_gates_after_engine_status` (the `allSettled` list now
   includes `loadLanguages()`), `test_empty_state_and_preset_ids_exist` (`$("speak-text").lang = lang`).
3. The Test phrases column renders `N of max(6, N)` so an edited list longer than six never reads
   "8 of 6"; `None yet` and the unsupported note are unchanged.
4. `api.del` gained an optional body and `api.put` was added (both in `core.js`, an owned file) —
   `DELETE /api/languages/{code}` needs a body for the relabel/delete decision.
5. Nothing in `app/**.py` or `app/static/presets.json` was touched (step 10).
