# M2-T17 — Runner log safety + s6 restart backoff

- **Milestone:** M2
- **Wave:** 13
- **owns:** `app/engine_runner.py`, `deploy/s6/engine/finish`, `deploy/s6/engine/run`, `tests/test_engine_runner.py`, `tests/test_deploy.py`
- **deps:** M2-T15a
- **verify:** `.venv/bin/python -m pytest tests/test_engine_runner.py tests/test_deploy.py -q && .venv/bin/ruff check app/engine_runner.py tests/test_engine_runner.py tests/test_deploy.py`
- **requirements:** `ui/STARTING.md:34-40`, R-004

## Context

Review found: the runner opens the log with `"w"` while the tracker appends, so app lines get overwritten; strict UTF-8 decoding can kill the supervisor and orphan the engine; a missing `vllm` writes nothing to the log; no backoff (s6 restarts immediately, `restart_in_s` impossible); SIGKILL of the runner can orphan the child.

## Steps

1. `app/engine_runner.py`:
   - Truncate the log once at start (`write_text("")`), then open with `"a"` (O_APPEND) so tracker appends and engine lines never clobber each other; count bytes via `stat().st_size` for rotation and cap individual lines at 8 KiB.
   - `Popen(..., encoding="utf-8", errors="replace")`; `_echo` catches `UnicodeError` as well as `OSError`.
   - `Popen` in `try/except OSError` → log/stdout `[engine] failed to start: <exc>`, exit 127.
   - `preexec_fn` sets `PR_SET_PDEATHSIG=SIGTERM` via `ctypes` on Linux (best effort) so a killed runner does not orphan vllm; keep `start_new_session` + process-group signal forwarding.
   - On exit write `[engine] exited with code N` (planned stop 0/143) and the epoch to `$DATA_DIR/logs/engine-last-exit` (for the tracker's countdown).
2. `deploy/s6/engine/finish` (new, executable):
   - Compute the effective code (handle `$1 == 256` + `$2` signal); planned `0/143` → exit 0 without backoff.
   - Increment `/run/engine-failures`; write epoch to `/run/engine-last-exit`.
   - Sleep 30 s (first), 60 s (second), 120 s (third); after the third, `touch /run/service/engine/down` and exit so s6 stops restarting until a manual restart.
   - `run` unchanged (`exec python3 -m app.engine_runner`).
3. Tests:
   - Update runner tests for the append mode (pre-existing app line survives engine writes), invalid UTF-8 bytes handled, missing command → 127 + log line, rotation by bytes, line cap.
   - SIGKILL orphan test (Linux): kill the runner with SIGKILL, poll that the child exits within a few seconds.
   - `tests/test_deploy.py`: assert `finish` exists/executable, has 30/60/120 and the down marker, and that `run` still execs the runner.
4. Do not edit the tracker or app code.

### Deviations

- Rotation semantics: the write that pushes `st_size` past the cap lands in `engine.log.1`
  (rename happens after the write), the next line starts the fresh file — standard
  rename-rotation, asserted explicitly in `test_rotation_counts_file_size_not_own_writes`.
- Startup truncation implemented exactly as the brief says (`write_text("")` once, then append);
  the "pre-existing app line survives" test therefore appends the `[app]` line *while the
  runner runs* — the real tracker flow — instead of pre-seeding the file, which the
  once-at-start truncate would erase by design.
