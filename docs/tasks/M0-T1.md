## Context

SPEC §12 defines six spikes (S1 style control, S2 voice design, S3 streaming format, S4 sampling
knobs, S5 warm-up, S6 Qwen3 shim fields). No engine is reachable from this machine (Q-001), so the
deliverable is a runnable script per spike plus `NOTES.md` describing how to run them and what each
result means for the implementation. Do **not** invent findings.

The engine base URL is `http://127.0.0.1:8881` on the `vllm` host (test container), or `:8102`
inside the production container. Read `docs/CONTRACTS.md` §5 for the request shape the app sends.

## Steps

1. `scripts/spikes/_client.py`: small stdlib/httpx helper — `parse_args()` (`--base`, `--voice`,
   `--audio`), `speech(...)` posting to `/v1/audio/speech`, `save(name, bytes)` writing to
   `scripts/spikes/out/` (gitignored output dir is fine).
2. One executable script per spike (`s1_style.py` … `s6_shim.py`), each printing a one-line JSON
   result and the interpretation. Real requests only; no stubs.
   - S1: send `instructions` vs the VoxCPM2 controllable-cloning syntax in `input`; report whether
     output changes (duration/hash) and whether the field is rejected.
   - S2: request synthesis with **no** `ref_audio` + `instructions=<description>` + explicit
     `seed`; try two seeds and report whether output differs. Record the exact accepted payload.
   - S3: non-streamed WAV vs `stream=true&response_format=pcm` for the same input; decode the
     stream as s16le at 48 kHz, report bytes, seconds, first-chunk ms, and the
     streamed-vs-WAV duration delta (spec observed 7.69 s vs 5.76 s).
   - S4: send `cfg`, `steps`, `seed` as top-level fields and (if rejected) under
     `extra_body`/`sampling_params`; report which shape is accepted.
   - S5: measure first request after start vs second/third; report seconds saved.
   - S6: print the exact command to read `/opt/app/app/openai_api.py` from the `qwen3-tts-openai`
     container and a checklist of request fields to capture; if `--shim-json` fixture path is
     given, parse field names. No container introspection is possible here.
3. `NOTES.md`: one section per spike with **Status: not run (requires vllm host)**, the exact
   command, the decision the result controls, and a placeholder table row for the observed result.
   Include a top note: M0 is blocked externally (Q-001); implementation uses SPEC fallbacks until
   the spikes run.
4. `scripts/spikes/README.md`: host-run instructions and where output files land.
