## Context

`ui/STARTING.md` is the contract. `app/engine_runner.py` now writes
`$DATA_DIR/logs/engine.log`; `app/static/starting.html` polls `/ready` and
`/api/engine/startup`. Implement the server side:

- While not warm and `STARTUP_PAGE` (default true): `GET /` serves `starting.html`; `/api/*` returns
  503 + `Retry-After: 5` except `GET /api/engine/startup` and `POST /api/engine/restart`.
- `GET /api/engine/startup` returns the documented JSON (state, elapsed_s, 4 steps, error,
  restart_in_s, last 16 log lines).
- `/api/engine/restart` resets the tracker before restarting.

## Steps

1. `app/startup.py` — `StartupTracker(settings, store, engine, warmup)`:
   - `t0` at construction; `mark_container_started(voice_count)` sets step 1 done and detail.
   - Steps: 1 Container started, 2 Loading model weights, 3 Starting the engine, 4 Warming up.
     At most one `active`/`failed`. Details:
     1. `App online, voice library loaded (N voices)`
     2. `openbmb/VoxCPM2 · 4.7 GB from <MODEL_PATH>` (or `from <path>` from settings)
     3. `vLLM-Omni <version> · <kv> KV cache · <GPU>` (GPU from `engine.stats().gpu`, fall back to
        "GPU")
     4. `One full and one streamed synthesis, so the first real request is fast`
   - Step transitions: step 1 done at mark; step 2 done when the log contains
     `Model loading took` **or** `engine.ready`; step 3 done when `engine.ready`; step 4 done when
     `warmup.warm`. Record `duration_s` when observed.
   - Log: read `$DATA_DIR/logs/engine.log` tail (last 200 lines, strip ANSI, trim 200 chars) and
     append app events with `[app] ` prefix to the same file (append mode, never raise). Return the
     last 16 lines. Events: library loaded, waiting for engine, engine health OK, warm-up done.
   - Failure: a fatal line (`CUDA out of memory`, `No module named 'voxcpm'`,
     `Engine core initialization failed`, `[engine] exited with code`) **or** elapsed >
     `settings.startup_fail_after_s` without `engine.ready`. Mark the current step `failed`, set
     `state="failed"`, `warmup.warm=False`, and map `error`:
     - CUDA → "CUDA out of memory while allocating the KV cache. Another process may be using GPU memory."
     - module → "The voxcpm package is missing from the image. Rebuild with voxcpm installed via uv."
     - exit → "The engine process exited with code N. See the engine log."
     - timeout → "The engine did not become healthy within N seconds. See the engine log."
     - else → "The engine failed to start. See the engine log."
   - `state` is `ready` when `warmup.warm`; `restart_in_s` is always null (s6 restarts immediately;
     keep the key for the contract).
   - `reset()` clears state/durations/errors, sets a new `t0`, logs `[app] Restart requested`.
   - `snapshot() -> dict` (sync); the route calls it via `asyncio.to_thread`.
2. `app/main.py`:
   - Lifespan: create `StartupTracker` after stores/warmup, `mark_container_started(len(store.list()))`,
     expose `app.state.startup`.
   - `GET /`: if `settings.startup_page` and startup state != ready → `FileResponse(starting.html)`;
     else index.
   - Middleware (registered **before** the Basic-auth middleware so auth still runs first): when
     `settings.startup_page` and `startup.state != "ready"`, `/api/*` → 503 OpenAI body +
     `Retry-After: 5`, except `/api/engine/startup` and `/api/engine/restart`.
   - Do not gate `/v1`, `/health`, `/ready`, `/static`.
3. `app/routers/studio_engine.py`: `GET /api/engine/startup` (Studio auth already applies) returns
   `await asyncio.to_thread(startup.snapshot)`; `POST /api/engine/restart` calls
   `startup.reset()` first.
4. `tests/test_startup.py`:
   - Unit: fake log file + stub engine/warmup → starting with step 1 done, step 2 active; after
     setting engine ready → step 3 done; after warmup warm → state ready, all durations set.
   - Fatal CUDA line → failed step 3/2 with the exact message; `[engine] exited with code 2` →
     code message; `startup_fail_after_s=0` → timeout message; log tail is 16 lines, ANSI stripped.
   - App with `startup_page=True` and a dead engine: `/` returns starting.html ("Starting the voice
     engine"), `/api/voices` 503 + `Retry-After`, `/api/engine/startup` 200 with the 4 steps,
     `/api/engine/restart` not 503 (502 acceptable), `/health` 200, `/v1/audio/speech` not 503
     from the gate (engine error shape is fine).
   - Once `warmup.warm=True` and `engine._ready=True`: `/` returns the Studio (contains
     `screen-speak`) and `/api/voices` 200.
5. `tests/e2e/test_startup.py`: live app (`startup_page=True`, dead engine URL,
   `startup_fail_after_s=2`): load `/`, assert the starting page renders steps and elapsed; wait for
   the failed state ("The voice engine didn’t start") and the restart button; screenshot
   `test-results/ui-starting-1280.png` and `ui-starting-failed-1280.png`. Keep it deterministic with
   `wait_for`/polling, no fixed long sleeps.
6. Do not edit static assets or other routers.

### Deviations

- `reset()` keeps step 1 `done` (with its duration) and clears steps 2–4 — the brief says "clears
  durations" but `ui/STARTING.md` ("resets the startup state to step 2") is the contract and wins.
- `[engine] exited with code N` is fatal only for unplanned codes; 0/143/130 (planned s6 stop /
  SIGINT, per `app/engine_runner.py`) are not — otherwise every restart would self-fail on its own
  stop line.
- Fatal lines are scanned only past a byte watermark (set at construction and on `reset()`), so an
  old crash line cannot re-fail a fresh attempt; a failure also clears once `engine.ready` again
  (s6 auto-recovery) until the next new fatal line.
- Gate 503 body uses `code: "startup_in_progress"` (contract only fixes the OpenAI shape +
  `Retry-After: 5`); this is how tests distinguish the gate from the engine's own `engine_not_ready`.
- e2e keeps `startup_fail_after_s=2` as briefed; the "starting" assertions are state-independent
  (4 steps + elapsed) so the 2 s deadline cannot make the test flaky.
