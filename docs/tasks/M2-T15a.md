# M2-T15a — Engine log capture (`engine_runner`) and s6 wiring

- **Milestone:** M2
- **Wave:** 11
- **owns:** `app/engine_runner.py`, `deploy/s6/engine/run`, `tests/test_engine_runner.py`, `tests/test_deploy.py`
- **deps:** M1-T3
- **verify:** `.venv/bin/python -m pytest tests/test_engine_runner.py tests/test_deploy.py -q && .venv/bin/ruff check app/engine_runner.py tests/test_engine_runner.py tests/test_deploy.py`
- **requirements:** R-004, R-046, startup page contract (`ui/STARTING.md`)

## Context

The new startup page (`ui/STARTING.md`) needs the engine log tail and plain-language failure
mapping. The s6 engine service currently execs `vllm serve` directly, so its output only reaches
container stdout and the app cannot read it. Add a small supervisor wrapper that tees the engine
output to `$DATA_DIR/logs/engine.log` while preserving stdout and signal handling.

## Steps

1. `app/engine_runner.py` (stdlib only):
   - Build argv from env: `MODEL_PATH`, `DEPLOY_CONFIG`, `ENGINE_PORT`, `ENGINE_MODEL`
     (default `openbmb/VoxCPM2`): `vllm serve <model> --omni --deploy-config <cfg>
     --served-model-name <name> --host 127.0.0.1 --port <port>`.
   - Allow `ENGINE_COMMAND` (shlex-split) as a test hook; otherwise use the argv above.
   - Log file `$DATA_DIR/logs/engine.log`: create the dir, truncate at start, append every
     stdout/stderr line (merged, line-buffered), rotate to `.1` when > 2 MB.
   - Tee each line unchanged to `sys.stdout` (container logs).
   - `subprocess.Popen(..., stdout=PIPE, stderr=STDOUT, text=True, bufsize=1,
     start_new_session=True)`; forward SIGTERM/SIGINT to the process group; on exit append
     `[engine] exited with code N` to the log/stdout and exit with that code (0/143 on planned
     stop).
   - Never crash if the log file cannot be written; stdout still works.
2. `deploy/s6/engine/run`: `#!/command/with-contenv sh` + `cd /opt/app && exec python3 -m
   app.engine_runner` (no direct `vllm serve` in the s6 file).
3. `tests/test_engine_runner.py`:
   - Run the module in a subprocess with `ENGINE_COMMAND="python3 -c 'print(...)'"` and a temp
     `DATA_DIR`; assert stdout and the log both contain the lines, `[engine] exited with code 0`
     is appended, exit 0.
   - Non-zero command exit → same exit code, log records it.
   - Sigterm/terminate: start a sleeping command, send SIGTERM to the runner, assert the child is
     reaped and exit is 143/0 as documented.
   - Rotation: pre-fill > 2 MB then run a short command; `.1` exists and the new log is small.
4. `tests/test_deploy.py`: update the engine-service assertions — `run` must exec
   `app.engine_runner`, the runner file must contain `vllm serve`, `--omni`, `--deploy-config`,
   `127.0.0.1` and `$ENGINE_PORT`; keep the with-contenv assertion.
5. Do not edit other app files.

## Report

### Files changed

- `app/engine_runner.py` (new, stdlib only) — builds the engine argv from `MODEL_PATH`,
  `DEPLOY_CONFIG`, `ENGINE_PORT`, `ENGINE_MODEL` (default `openbmb/VoxCPM2`), honours the
  `ENGINE_COMMAND` shlex-split test hook, spawns the child with
  `Popen(stdout=PIPE, stderr=STDOUT, text=True, bufsize=1, start_new_session=True)`, tees every
  line to `sys.stdout` (flushed) and to `$DATA_DIR/logs/engine.log`, rotates to `engine.log.1`
  when the file is over 2 MB (at start and mid-run), forwards SIGTERM/SIGINT to the child's
  process group, and appends `[engine] exited with code N`. A signal death is reported shell-style
  (`128 + signum`, so SIGTERM → 143); a clean stop exits 0. Log failures (missing/unwritable
  `DATA_DIR`) are swallowed so stdout keeps working.
- `deploy/s6/engine/run` — now `#!/command/with-contenv sh` + `cd /opt/app && exec python3 -m
  app.engine_runner`; no `vllm serve` in the s6 file. Exec bit preserved (`-rwxr-xr-x`).
- `tests/test_engine_runner.py` (new, 7 tests) — default argv construction, stdout+log tee,
  non-zero exit propagation, SIGTERM (child pid recorded by the sleep script, asserted gone via
  `os.kill(pid, 0)`, runner exit 143/0), rotation at start (2 MB+10 pre-fill → `.1` byte-identical,
  new log small), mid-run rotation (unit-level on `EngineLog`), unwritable `DATA_DIR` still prints.
- `tests/test_deploy.py` — `test_engine_is_longrun_with_documented_command` now asserts
  with-contenv + `exec … app.engine_runner` and that the run file no longer mentions vllm; new
  `test_engine_runner_builds_the_documented_command` pins `vllm serve`, `--omni`,
  `--deploy-config`, `--served-model-name`, `127.0.0.1`, `$ENGINE_PORT` in the runner source and
  keeps the loopback-only (`0.0.0.0` absent) assertion. Other assertions untouched.

### Deviations

- SPEC §4 L69 says the s6 `engine` service runs `vllm serve …` directly. Per this brief the run
  script now execs `app.engine_runner`, which execs the identical command; R-004's substance is
  preserved and pinned by `test_engine_runner_builds_the_documented_command`. Flagging for the
  lead in case SPEC.md wants a one-line note.
- The runner also writes one line of its own to stdout/log —
  `[engine] running: vllm serve …` — so the startup page can show the resolved command. It does not
  match any phase/failure pattern in `ui/STARTING.md`.

### Assumptions / open questions

- Exit-code convention on a planned stop: child killed by SIGTERM → runner exits 143; child that
  exits cleanly after the signal → runner exits 0 (both accepted by the test, as the brief allows).
- `ENGINE_PORT`/`MODEL_PATH`/`DEPLOY_CONFIG` defaults mirror `app/config.py` (`8102`,
  `/models/openbmb/VoxCPM2`, `/opt/app/deploy/voxcpm2-3090.yaml`); env always wins.
- Rotation keeps only one `.1` generation (matches the brief); no size cap on `.1` itself.
- The startup tracker that reads this log (`/api/engine/startup`) is a sibling task — nothing here
  depends on it, and no other app file was touched.
