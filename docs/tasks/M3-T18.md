- **requirements:** SPEC §8 (takes, design candidates, Voices edit), reported UI bugs

## Context

Reported: play/pause and waveform progress are unreliable on Speak, Design candidates have no player
state at all, Download is vertically misaligned with Save as voice, and the Voices inline editor
misaligns the table. Root causes found:
- Speak auto-plays the new take after Generate; a user click then pauses it (looks like “play did
  nothing”), and the player callback state is duplicated per screen.
- Design calls `play(url)` with no callback, so no pause icon, row highlight or waveform progress.
- `.btn-link` is used for `<a>` and `<button>` with different default alignment.
- The Voices editor is a single `colspan=6` grid, so it does not line up with the table columns.

## Steps

1. `core.js`: add `attachPlayer({url, row, btn, icon, wave})` backed by the existing shared
   `play()/setWaveProgress()`:
   - button click toggles play/pause; icon path switches triangle↔pause; `aria-label`/`title`
     Play/Pause; row gets `.is-playing`; on `stop`/ended reset icon, row class and progress to 0.
   - rAF progress 0..currentTime/duration plus the `time` event as a fallback.
   - callable for speak takes and design candidates; one active player.
   Refactor `speak.js` to use it (remove its local `syncPlayer`/rAF globals) and ensure the
   post-Generate auto-play sets the row state correctly.
2. `design.js`: use the same binding for candidate rows (row `.vs-cand`, wave clip overlay,
   play/pause icon, `.is-playing` highlight). Selecting a candidate still works independently.
3. `studio.css`:
   - `.vs-take .links { align-items: center; }`
   - `.btn-link, a.btn-link { display: inline-flex; align-items: center; line-height: 1;
     vertical-align: middle; }` so Download and Save as voice share a baseline/height.
   - `.vs-cand.is-playing { background: var(--vs-code-bg); }` and its accent wave overlay.
4. `voices.js`: rewrite the editor as a **normal table row** (no colspan):
   - Name cell → `<input>`; Language cell → `<select>`; Source/Reference cells keep their text;
     Transcript cell → auto-growing `<textarea>` with an “Auto-transcribe” button under it;
     Actions cell → Save + Cancel (Edit becomes Save).
   - Inputs/select/textarea fill their cell (`width:100%`), no horizontal/vertical scrollbars, row
     height grows with the textarea; Save re-renders a normal row with the transcript clamped to
     one line.
   - Keep focus management, busy guard, and inline errors.
5. Tests:
   - static: attachPlayer exported, no local rAF in speak, design uses attachPlayer, editor has no
     colspan (or asserts cells), link alignment CSS.
   - e2e: generate a take, wait for auto-play to finish/stop, click play → Pause icon + `.is-playing`
     + clip width grows; click again → Play icon + width stops; Design generate candidates, click
     play → same states; Voices Edit keeps header/columns aligned (compare cell x positions before
     and after), textarea grows, Save collapses; Download/Save as voice bounding-box tops match.
6. Do not edit Python.

## Report

### Files changed

- `app/static/js/core.js` — new `attachPlayer({url, row, btn, icon, wave, label})` on top of the
  existing shared `play()`/`setWaveProgress()`: click toggles play/pause, the icon path swaps
  triangle↔pause, `aria-label`/`title` become Play/Pause, the row gets `.is-playing`, rAF paints the
  playhead with the `time` event as fallback, and `stop`/ended resets icon, row class and progress
  to 0. Returns `{ play }` so a screen can auto-play without owning state.
  **Root cause found while wiring this:** the old `syncPlayer` treated `timeupdate` as
  "not playing" (`classList.toggle("is-playing", phase === "play")` ran on every phase), so the
  first `timeupdate` (~250 ms in) dropped the pause icon, the row highlight and the rAF loop — that
  is the reported "play did nothing / progress unreliable". `attachPlayer` only changes state on
  `play`/`pause`/`stop`; `time` moves the playhead and nothing else.
- `app/static/js/speak.js` — deleted the local `syncPlayer`, `PLAY_D`/`PAUSE_D`, `raf` and `firstUi`
  globals; the take row now calls `attachPlayer(...)` and the post-Generate auto-play is
  `firstPlayer.play()`, so the auto-played row shows the same state as a clicked one.
- `app/static/js/design.js` — candidate rows get the same binding (`label: "candidate N"`) plus the
  Speak-style wave (grey base + accent overlay clipped to `#cd-<id>`); the stateless
  `play(playBtn.dataset.url)` branch is gone, and `stopAudio()` runs when the rows are replaced.
- `app/static/studio.css` — `.vs-take .links { align-items: center }`;
  `.btn-link, a.btn-link { display: inline-flex; align-items: center; line-height: 1;
  vertical-align: middle }` so `<a>` Download and `<button>` Save as voice share one box;
  `.vs-cand.is-playing` background + accent wave overlay; the editor grid rules replaced by
  normal-row rules (`.vs-edit td`, `.vs-edit-txcell`, `.vs-edit-tx`, and
  `width: 0; min-width: 100%` on the controls so they fill the cell without changing column
  widths). Also moved the one-line transcript clamp from `td.tx` to `td.tx > span`: a `max-width`
  on the cell let one long transcript move that row's columns (measured: 166 → 143 px), which is
  the same misalignment the brief reports.
- `app/static/js/voices.js` — the inline editor is now a normal table row (no `colspan`): Name →
  `<input>`, Language → `<select>`, Source/Reference reuse `sourceCell()`/the duration cell,
  Transcript → auto-growing `<textarea>` with Auto-transcribe under it, Actions → Save + Cancel.
  Focus management (`nameInput.focus()`), the `busy` guard and inline errors are unchanged;
  `voiceRow()` and `openEditor()` share the Source/Reference cell builders.
- `tests/test_ui_assets.py` — player assertions moved to `core.js` (attachPlayer exported, no local
  rAF in `speak.js`, `time` never changes state), new candidate-binding test, link-alignment CSS,
  editor-is-a-normal-row test (six cells, no `colSpan`).
- `tests/e2e/test_studio.py` — `_new_take()` now non-stream, waits for the auto-play to start and
  then to stop (asserts the row resets to Play + progress 0); play → Pause icon/`.is-playing`/clip
  width grows, pause → width frozen; new Design candidate player test (same states, second row
  takes over, Select still works); Download/Save-as-voice box tops+heights match; the editor test
  compares every row's cell x against the header's six-column grid before Edit, while editing,
  after Save and after restoring the transcript.

### Deviations

- The brief's e2e sketch "compare cell x positions before and after" is implemented as *every row
  against the header grid* at four moments. Auto table layout legitimately re-flows the whole table
  when a transcript's content changes (measured: the Transcript column 413 → 549 px), so a literal
  before/after x comparison would fail for reasons unrelated to the editor; what must not change is
  rows disagreeing with each other, and that is what is asserted.
- Extra fix inside `owns:`: the `td.tx { max-width }` → `td.tx > span` move described above. Without
  it a saved long transcript visibly misaligns the Voices table, which is the bug class this task is
  about. No Python under `app/` was touched.
