## Context

Human decision (2026-11-02): Studio must synthesize through `/api/speak` (covered by Studio Basic
auth), not `/v1`, so the browser never needs an API key. Format must be real, not disabled.

Contracts are amended in `docs/CONTRACTS.md` §2–§3:
- `POST /api/speak?save=false` → audio bytes in `response_format`, **no take**, headers
  `X-Voice`, `X-Sample-Rate` (streaming: same headers, no `X-Take-Id`).
- `POST /api/speak` (default `save=true`) → unchanged `TakeInfo`, plus the stored `format`.
- `GET /api/takes/{id}/audio?format=…` → transcode the stored WAV to the requested container.

## Steps

1. `app/models.py`: add `format: str = "wav"` to `TakeInfo`.
2. `app/routers/studio_takes.py`:
   - Add `save: bool = True` and keep `stream` in `SpeechRequest`; route signature
     `async def speak(request, payload, save: bool = True)`.
   - `save=false`: do **not** create a take. Non-stream → `speech.synthesize(payload)` and return
     `Response(result.audio, media_type=result.media_type, headers={X-Voice, X-Sample-Rate})`.
     Stream → `await speech.stream(payload)` and stream with `aclose` in `finally`/background but no
     `X-Take-Id` and no persistence.
   - `save=true`: store the take with `extra={"format": payload.response_format}`; take playback
     remains WAV on disk (`format` records what the Studio asked for).
   - `GET /api/takes/{id}/audio`: query params `format: str = ""` (fallback: take JSON `format` or
     `wav`) and `sample_rate: int | None`. Decode the stored WAV in a thread, transcode with
     `audio.transcode(..., target_rate=..., speed=1.0)`; return the matching media type; validate
     the format against `audio.MIME_TYPES` (400 otherwise).
   - `TakeInfo` construction includes `format=take.get("format", "wav")`.
3. Tests:
   - `save=false` non-stream `response_format="mp3"` → `audio/mpeg`, no take created, `X-Voice`
     present, no `X-Take-Id`.
   - `save=false&stream=true` pcm → audio chunks, no take, no `X-Take-Id`.
   - normal `save=true` mp3 request → `TakeInfo.format == "mp3"`, stored WAV is 48 kHz, and
     `GET audio_url?format=mp3` returns `audio/mpeg`; `?format=pcm` returns s16le; invalid format → 400.
   - `save=false` works with `ref_audio` (ad-hoc) and leaves `store.list()` unchanged.
   - Existing takes tests stay green.
4. Do not edit speech/engine/UI or fixtures.

### Deviations

1. **Streamed saves do not record `format`.** Brief step 2 reads as "all `save=true`", but recording
   the streamed container would make the default (no `?format=`) playback URL return raw s16le or an
   unknown-length streamed FLAC — both break the existing
   `test_every_streamed_format_saves_a_take[pcm|flac]`, which must stay green, and the frozen UI's
   `play(take.audio_url)` (`app/static/js/speak.js:92,191`). The streamed container is transient and
   the take on disk is a 48 kHz WAV, so its format *is* `wav`. Non-stream saves record the requested
   container exactly as the brief says.
2. **No explicit `format=take.get("format", "wav")` in the `TakeInfo(...)` calls** (step 2, last
   bullet). `TakeInfo(**take, **take_urls(...))` already carries the key when present and the new
   model default covers takes written before this task; adding the kwarg would duplicate it.
   Verified by `test_take_audio_format_falls_back_to_stored_format` (`legacy["format"] == "wav"`).
3. **`X-Voice` on the streamed path** now comes from `safe_header_value(streaming.key or
   streaming.voice)` — the same rule `/v1` uses — instead of `payload.voice`, so a caller that passes
   a display name gets the ASCII lookup key. Existing assertions unchanged (`ashley-en`, `qwen-a`).
4. Preview non-stream passes the payload straight to `speech.synthesize` (so the request's
   `sample_rate`/`speed` apply to what you hear), while `save=true` still forces 48 kHz/speed 1.0 —
   that is what "Format is honored for previews" requires, and it is why the preview response carries
   `X-Sample-Rate` from the result.
