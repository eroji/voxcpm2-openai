# M1-T15 — Move speech decode/transcode/data-URI work off the event loop

- **Milestone:** M1
- **Wave:** 8
- **owns:** `app/speech.py`, `tests/test_speech.py`
- **deps:** M1-T9, M1-T12
- **verify:** `.venv/bin/python -m pytest tests/test_speech.py -q && .venv/bin/ruff check app/speech.py tests/test_speech.py`
- **requirements:** R-007, R-015, R-016

## Context

Release review: `synthesize()` runs `store.resolve()` (disk read + WAV encode + base64),
`read_audio()` and `transcode()` (`subprocess.run`) directly on the event loop. A long non-streamed
request can block `/health`, `/ready`, and every queued request, breaking the 2-slot queue model.

## Steps

1. `synthesize()`:
   - `voice = await asyncio.to_thread(self.resolve, request)`.
   - `samples, sample_rate = await asyncio.to_thread(audio_utils.read_audio, result.audio)`.
   - `encoded = await asyncio.to_thread(audio_utils.transcode, samples, sample_rate, fmt,
     target_rate=..., speed=...)` (keyword args work with `to_thread`; use `functools.partial` if
     needed).
2. `stream()`: `voice = await asyncio.to_thread(self.resolve, request)`; the rest stays.
3. Keep signatures, error mapping and 48 kHz rules unchanged.
4. Test: monkeypatch `audio_utils.transcode` (and `read_audio`) with a blocking `time.sleep(0.3)`;
   run `synthesize` concurrently with a ticker task and assert the ticker ran ≥3 times during the
   call (proves the loop was not blocked). Also assert the normal path still returns the same
   duration/header values.
5. Do not edit routers, engine or audio.

## Definition of done

- [x] `verify:` green; output in `## Report`.
- [x] A blocking transcode no longer stalls the event loop.

### Open questions

- `asyncio.to_thread` uses the default `ThreadPoolExecutor`. Under sustained load the default pool
  (min(32, cpu+4)) could saturate if many long transcodes overlap with the 2-slot queue. If that
  ever shows up, a dedicated bounded executor is the upgrade path — not needed for the 2+16 model
  (Q-016), so left as-is.
