## Context

Wave-3 review found that an imported voice with `name="Ashley EN"` and `voice_name_lower="ashley-en"`
is now imported correctly but is **unreachable from the UI**: `VoiceSummary` exposes only the
display name, while `VoiceStore.get()` validates/normalizes names, so `"Ashley EN"` fails (space) on
`/api/voices/{name}`, PATCH/DELETE, and `/api/speak`. SPEC §5 defines `voice_name_lower` as the
lookup key. Also: a hand-placed uppercase filename (`Ashley-en.safetensors`) is listed under the
lowercase key but every path lookup misses; and `TakeStore._wave_cache` is unbounded.

The lead has added `key` to `VoiceSummary`/`CONTRACTS`; `Voice.summary()` already returns it.

## Steps

1. `VoiceStore`:
   - `_read_voice_file`: reject/normalize a stem that is not already the lowercase key — return the
     voice keyed by `path.stem` only when `path.stem == validate_voice_name(path.stem)`; otherwise
     skip the file in scans (do not list a voice that cannot be fetched).
   - Keep `get(name)` case-insensitive (it validates/lowercases), and make `list()` consistent with
     `get()`.
2. `TakeStore._wave_cache`: cap at 64 entries with insertion-order eviction (same policy as the
   voice URI cache).
3. Tests:
   - Create a voice with display `"Ashley EN"`/key `ashley-en` (via `create(..., key="ashley-en")`);
     `summary()` returns `key="ashley-en"`, `name="Ashley EN"`; `get("ashley-en")`,
     `read_audio("ashley-en")`, `data_uri("ashley-en")` work; `list()` shows it once.
   - Drop an uppercase-named safetensors file into `voices/`; `list()` omits it and no route would
     produce a 500 (assert `get(stem)` still 404s cleanly if called).
   - Create > 64 takes with distinct wave calls; `_wave_cache` length ≤ 64.
   - Existing store tests stay green (summary now includes `key`).
4. Do not edit models, routers, importer or fixtures.
