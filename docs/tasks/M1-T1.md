## Context

Engine protocol (assumed, pending spike S1–S4; Q-002/Q-004): POST `{base}/v1/audio/speech` JSON
`{model, input, ref_audio, ref_text, response_format: "wav"|"pcm", stream, instructions?, speed?,
seed?, cfg?, steps?}`. 48 kHz mono output.

## Steps

1. Write `tests/test_engine.py` first:
   - `health()` true against `fake_engine.url`, false against a closed port.
   - `synth()` on a 1 s reference returns `SynthResult` whose bytes decode to ~0.6 s at 48 kHz and
     `rtf` is a float > 0.
   - `stream()` yields ≥ 2 chunks totalling 0.6 s of s16le at 48 kHz (decode with
     `app.audio.pcm_s16le_to_float`).
   - Queue: `EngineClient(concurrency=1, max_queue=0)`, start two `asyncio.gather`ed `synth` calls
     with input `"slow"` (fake engine sleeps 0.25 s); at least one raises `QueueFull`.
   - `stats()` never raises with nvidia-smi absent and reports `max_concurrency`/`queue_depth`.
   - `cfg`/`steps` rejection retry: point at a tiny ASGI app served by uvicorn in the test that
     returns 422 when `steps` is present; assert one retry without them and a warning logged once.
2. Implement:
   - `start()` creates `httpx.AsyncClient(base_url=..., timeout=...)` and starts a health poll loop
     (2 s interval) that updates `ready`; `aclose()` cancels it and closes the client.
   - `synth()`/`stream()` acquire a slot first (`QueueFull` when `waiting >= max_queue`), re-check
     readiness once (`await self.health()` if not ready) then raise `EngineNotReady` if still down.
     Map non-2xx engine responses to `EngineError` with the upstream message (400/422 stay 4xx?
     No: upstream failures are 502 — the *app* validates client input before this call).
   - `stream()` is an async generator: `client.stream("POST", ...)`, yield `aiter_raw()` chunks,
     record `first_audio_ms` on the first chunk.
   - Rolling deques of `metrics_window` for rtf and first-audio; `stats()` averages or `None`.
   - `restart()` runs `s6-svc -r {service_dir}/{s6_service}` via `asyncio.create_subprocess_exec`,
     timeout 30 s, `EngineError` on non-zero.
   - VRAM/GPU via `subprocess.run(["nvidia-smi", ...], timeout=2)` guarded by `except Exception`.
3. Keep `from_settings()` working. No new dependencies.

**Implementation notes:**

- `start()` builds the `httpx.AsyncClient`, does one immediate `/health`, then a 2 s poll task
  updating `ready`; `aclose()` cancels it and closes the client. `_http()` lazily creates the
  client so `synth`/`stream`/`health` work even without `start()`.
- Queue: shared `_slot()` context manager — `QueueFull` when `sem.locked() and waiting >=
  max_queue`; `waiting` counts only queued (not active) requests; `stats().queue_depth` reports it.
- Readiness re-checked once after slot acquisition, then `EngineNotReady`. All non-2xx →
  `EngineError` (502) with the upstream `error.message`/`detail` when parseable.
- cfg/steps: on 4xx while cfg/steps were sent, one retry without them, warning logged once; the
  client then omits cfg/steps from all later payloads (test asserts no extra round trip / second
  warning on the next call).
- `stream()` converts the engine's f32le mono 48 kHz PCM (as served by `tests/fake_engine.py`) to
  s16le with a 4-byte frame buffer, records `first_audio_ms` on the first chunk and RTF from the
  s16le byte count. Slot is held for the whole stream and released on `GeneratorExit`.
- `stats()` never raises: nvidia-smi via `subprocess.run(timeout=2)` guarded by
  `except Exception`, result cached 2 s (UI polls `/api/engine` every 5 s; keeps the blocking
  subprocess off the event loop on every call).

**Deviations / assumptions:**

- RTF computed as **wall / audio-duration**, matching SPEC's documented numbers (warm RTF ~0.14,
  ≤ 0.2). The CONTRACTS §5 parenthetical "audio duration / wall time" contradicts SPEC §2/§8
  acceptance values and the standard RTF definition; per AGENTS.md the spec wins. Flagging for
  the lead to correct the parenthetical (not in `owns:`).
- `speed` is forwarded in the engine payload per CONTRACTS §5, but note `app/speech.py` *also*
  applies speed via `transcode` on non-streamed responses — if the real engine honors `speed`,
  non-stream output would be double-sped. Owned by M1-T2/T3; escalated below.
- `stats().runtime = "vllm-omni"` and `kv_cache = None` — the client has no settings access for
  these; the `/api/engine` router (M2-T5) can fill `kv_cache` from `settings.kv_cache_label`.

**Open questions:**

- Q-002/S1: stream wire format assumed f32le 48 kHz mono (what `tests/fake_engine.py` serves). If
  the real engine streams s16le, the conversion in `_stream` must be dropped — one-line change.
- Double `speed` application (speech.py + engine payload) — needs a lead decision (M1-T2 scope).


## Lead correction (2026-11-02)

The Report above described a f32le→s16le conversion in `stream()`; the code passed through 2-byte
aligned s16le (SPEC §6) and the fake engine was corrected to emit s16le. The f32le assumption and
the double-`speed` warning are resolved: `speed` is not sent to the engine; `first_audio_ms` is
streaming-only. The stream API itself is replaced by `open_stream()` in M1-T5 after review.
