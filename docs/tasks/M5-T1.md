## Context

Write the operational documentation for build, deploy, cutover, rollback and CI/CD activation, plus
a smoke script that exercises a running deployment. Base it on SPEC §11/§13, `deploy/compose.yaml`,
`deploy/Containerfile`, and the route table in `docs/CONTRACTS.md` §2. No secrets in either file.

## Steps

1. `docs/RUNBOOK.md` sections:
   - **Build & push** `harbor.dotslash.io/dotslash/voxcpm2-openai:0.1.0`; required Harbor CI
     variables (`HARBOR_USER`, `HARBOR_PASSWORD`, masked); what the `package` job does without them.
   - **Run on 8881** with `deploy/compose.yaml`; volumes; GPU CDI; data dir backup; `STUDIO_AUTH`
     and `API_KEYS` examples with placeholders (never real values).
   - **Acceptance** on 8881: the exact `scripts/smoke.sh` invocation, the eight voices, streamed
     first-chunk budget, queue behaviour, VRAM check.
   - **Cutover**: stop qwen3, move to 8880, LiteLLM alias, Open WebUI/Hermes/Wyoming checks.
   - **Rollback**: restore qwen3 + LiteLLM target; keep `/opt/qwen3-tts` for a week.
   - **Turning on CD**: set `DEPLOY_TARGET=staging|production`, `DEPLOY_HOST`, `DEPLOY_PATH`,
     `DEPLOY_SSH_KEY`; production requires a `vX.Y.Z` tag + manual approval. State clearly that CD
     is off by default and untested here.
   - **M0 spikes**: the host commands from `NOTES.md` and where to record results.
2. `scripts/smoke.sh`: POSIX-friendly bash, `set -euo pipefail`; env `BASE_URL`
   (default `http://127.0.0.1:8881`), optional `API_KEY`, optional `VOICE` (default `ashley-en`).
   Checks: `/health` 200; `/ready` 200; `/v1/models` contains `voxcpm2`; `/v1/audio/voices` lists
   `$VOICE`; `POST /v1/audio/speech` WAV (assert `RIFF` magic + `X-Sample-Rate: 48000`); streamed
   PCM returns bytes within 2 s; `/api/engine` reports `ready:true`. Print PASS/FAIL per step and a
   summary; exit non-zero on failure. Use `curl` + `python3` only (no jq dependency); never echo the
   key.
3. Mention `scripts/verify.sh` as the pre-push local gate in the runbook.
