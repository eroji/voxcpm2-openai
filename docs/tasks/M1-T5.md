- **requirements:** R-007, R-016, R-020, Q-016

## Context

Wave-1 review found two BLOCKERs in the frozen stream path:

1. `EngineClient.stream()` is a lazy generator, so queue/readiness admission happens **after**
   Starlette sent `200`; a full queue or cold engine can never produce 429/503 (SPEC §4/§6).
2. An `ffmpeg`-encoded stream can hang on client disconnect (`await feeder` while stdout is not
   drained) and leak the engine slot forever, degrading capacity to zero.

The lead has amended `docs/CONTRACTS.md` §5 to require `open_stream()` that admits **before**
returning. Implement that contract.

## Steps

1. `app/engine.py`:
   - Replace the synchronous `stream()` with
     `async def open_stream(params) -> StreamHandle`. `StreamHandle` (module-level dataclass)
     exposes `chunks: AsyncIterator[bytes]` and `async def aclose() -> None`.
   - Admission inside `open_stream`: reuse the `_slot` accounting but acquire manually
     (`_acquire()`/`_release()`, same `QueueFull`/`EngineNotReady` semantics and the
     `waiting >= max_queue` boundary), then `_post(params, stream=True)`, then return a handle.
     On any error release the slot and close the response.
   - `chunks` is an async generator that yields s16le (2-byte aligned, `aiter_bytes`, not
     `aiter_raw`), records `first_audio_ms`/RTF, and in `finally` closes the response and releases
     the slot exactly once. `aclose()` is idempotent and safe after exhaustion.
   - Wrap transport failures (`httpx.HTTPError`, decode failure in `synth`) in `EngineError`.
   - `restart()`: wrap `create_subprocess_exec` in `try/except OSError` → `EngineError`.
   - cfg/steps retry only for `400/415/422` (a 429/500 must not permanently disable the knobs).
   - Keep `synth()`/`stats()`/`health()` behaviour; no new dependencies.
2. `app/speech.py`:
   - `SpeechService.stream()` must `handle = await engine.open_stream(...)` **before** returning;
     `StreamingSpeech.chunks` must close the handle on exhaustion/cancel
     (`try/finally: await handle.aclose()`).
   - `ffmpeg_stream()`: on exit/GeneratorExit, cancel the feeder task, kill the process if still
     running, `await proc.wait()` (suppress errors), close `chunks` (`await chunks.aclose()`), and
     drain/close stderr. Never `await feeder` while stdout is unread.
   - `_wav_native()`: `finally: await source.aclose()`.
3. `tests/test_stream_lifecycle.py` (use `fake_engine`, `asyncio`):
   - **429 before headers**: engine `concurrency=1, max_queue=0`; open one slow stream and hold it;
     a second `open_stream` raises `QueueFull` immediately.
   - **503 before headers**: `EngineClient` at a closed port → `open_stream` raises `EngineNotReady`.
   - **Boundary**: `concurrency=2, max_queue=16`; fire 20 `synth("slow")` concurrently → exactly 18
     are admitted (2 run + 16 wait), the other 2 raise `QueueFull`; no 5th failure.
   - **Cancel releases the slot**: open a stream, `await handle.chunks.aclose()`, then a normal
     `synth()` succeeds within 2 s.
   - **Transport error**: point at a server that closes the connection mid-body → `EngineError`.
   - **429 does not disable knobs**: fake engine returns 429 once; a later request still sends
     `cfg`/`steps`.
   - **restart missing binary**: monkeypatch `asyncio.create_subprocess_exec` to raise
     `FileNotFoundError` → `EngineError`.
4. Update the existing `tests/test_engine.py` stream test to `open_stream` (consume
   `handle.chunks`, then `handle.aclose()`), keep the rest.

### Deviations

- `StreamHandle.aclose` is a dataclass field typed `Callable[[], Awaitable[None]]` (the cleanup
  closure) rather than a method; `await handle.aclose()` behaves exactly as the contract describes.
- The mid-body transport-error test uses a raw socket server instead of uvicorn, because uvicorn's
  mid-stream exception handling is an internal detail; truncating a `Content-Length` body is
  guaranteed to surface as `httpx.RemoteProtocolError` → `EngineError`.
