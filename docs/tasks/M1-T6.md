## Context

Wave-1 review found the image would boot only on unverified assumptions: `ffmpeg`/`curl` are used at
runtime (transcoding, resampling, compose healthcheck) but never installed or checked; the runtime
`uv pip install` can upgrade FastAPI/Pydantic/numpy under vLLM; and inherited s6 service dirs from
the Qwen3 base image may start old engines or double-bind `:8000`.

## Steps

1. `deploy/Containerfile`:
   - Keep the existing proven base/uv/voxcpm install and NCCL sanity check.
   - Install only app deps the base may lack, without upgrading the engine stack:
     `soundfile safetensors python-multipart pydantic-settings` via
     `uv pip install --system --break-system-packages --no-cache`. Do **not** reinstall
     fastapi/uvicorn/httpx/numpy/pydantic.
   - Add a build-time import check for every runtime dep:
     `python3 -c "import fastapi, uvicorn, httpx, numpy, soundfile, safetensors, pydantic,
     pydantic_settings, multipart"`.
   - Assert `ffmpeg` and `curl` exist (`RUN ffmpeg -version >/dev/null && curl --version >/dev/null`);
     if the base lacks ffmpeg, install it with the distro package manager in the same layer.
   - Clean stale services: remove `engine`, `app` and any `qwen3*` service dirs plus their
     `user/contents.d` markers before copying ours; keep s6-overlay base bundles intact. Add a build
     check that no `run` file under `/etc/s6-overlay/s6-rc.d` mentions `qwen3` or `vllm serve` other
     than ours (`grep -R` guard).
   - `CMD []` so an inherited base command cannot start a second app.
2. `tests/test_deploy.py`: extend the static assertions — runtime installs are limited to the
   allowed package list; import check + ffmpeg/curl check + `CMD []` present; stale-service cleanup
   present; s6 engine/app run scripts unchanged requirements still pass.
3. Do not edit `deploy/voxcpm2-3090.yaml`, `deploy/compose.yaml`, `app/**`.
