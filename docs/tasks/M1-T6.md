## Context

Wave-1 review found the image would boot only on unverified assumptions: `ffmpeg`/`curl` are used at
runtime (transcoding, resampling, compose healthcheck) but never installed or checked; the runtime
`uv pip install` can upgrade FastAPI/Pydantic/numpy under vLLM; and inherited s6 service dirs from
the Qwen3 base image may start old engines or double-bind `:8000`.

## Steps

1. `deploy/Containerfile`:
   - Keep the existing proven base/uv/voxcpm install and NCCL sanity check.
   - Install only app deps the base may lack, without upgrading the engine stack:
     `soundfile safetensors python-multipart pydantic-settings` via
     `uv pip install --system --break-system-packages --no-cache`. Do **not** reinstall
     fastapi/uvicorn/httpx/numpy/pydantic.
   - Add a build-time import check for every runtime dep:
     `python3 -c "import fastapi, uvicorn, httpx, numpy, soundfile, safetensors, pydantic,
     pydantic_settings, multipart"`.
   - Assert `ffmpeg` and `curl` exist (`RUN ffmpeg -version >/dev/null && curl --version >/dev/null`);
     if the base lacks ffmpeg, install it with the distro package manager in the same layer.
   - Clean stale services: remove `engine`, `app` and any `qwen3*` service dirs plus their
     `user/contents.d` markers before copying ours; keep s6-overlay base bundles intact. Add a build
     check that no `run` file under `/etc/s6-overlay/s6-rc.d` mentions `qwen3` or `vllm serve` other
     than ours (`grep -R` guard).
   - `CMD []` so an inherited base command cannot start a second app.
2. `tests/test_deploy.py`: extend the static assertions — runtime installs are limited to the
   allowed package list; import check + ffmpeg/curl check + `CMD []` present; stale-service cleanup
   present; s6 engine/app run scripts unchanged requirements still pass.
3. Do not edit `deploy/voxcpm2-3090.yaml`, `deploy/compose.yaml`, `app/**`.

## Report

**Files changed:** `deploy/Containerfile`, `tests/test_deploy.py`, this brief (Report only).

**What changed**

- Runtime `uv pip install` layer reduced to `soundfile safetensors python-multipart
  pydantic-settings`; fastapi/uvicorn/httpx/numpy/pydantic are no longer reinstalled (the base
  pins them for the vLLM stack).
- Added build-time import check for all nine runtime modules.
- Added ffmpeg/curl layer: conditional `apt-get install -y --no-install-recommends ffmpeg` only
  if `command -v ffmpeg` fails, then `ffmpeg -version >/dev/null && curl --version >/dev/null`.
- Stale-service cleanup before `COPY deploy/s6/`: `rm -rf` of `engine`, `app`, `qwen3*` service
  dirs plus their `user/contents.d` markers; s6-overlay base bundles untouched.
- Post-copy grep guard: any `run` file under `/etc/s6-overlay/s6-rc.d` (excluding our
  `engine/run`) mentioning `qwen3` or `vllm serve` fails the build.
- `CMD []` appended so an inherited base command cannot start a second app.
- Kept: base image, `voxcpm==2.0.3` via uv, vllm/NCCL sanity checks, ENV block, s6 copy/chmod.
- Tests: replaced `test_runtime_python_deps_installed` with `test_runtime_installs_limited_to_allowed_packages`
  (exact package list + no engine-stack tokens in any install layer) and added tests for the

**Base-image assumptions the host build must confirm (DoD item 3):**

1. Base is Ubuntu-family with `apt-get` — assumed for the conditional ffmpeg install; if the base
   lacks ffmpeg *and* apt, the `ffmpeg -version` assertion fails the build loudly (no silent gap).
2. `curl` is assumed present in the base (compose healthcheck uses it); the build asserts it.
3. Inherited service dir names (`engine`, `app`, `qwen3*`) — the grep guard catches any other
   name that actually starts an engine, so a wrong guess cannot ship a double-bind.
