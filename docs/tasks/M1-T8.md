## Context

Wave-2 review: installing `pydantic-settings` can still upgrade `pydantic` transitively, defeating
the "don't touch the engine stack" goal; the stale-service grep only looks for `qwen3|vllm serve`,
so a base service running `uvicorn ...:8000` would still double-bind; and the reference-config test
only asserts the files exist, so it cannot detect an edit to the read-only YAML/compose.

## Steps

1. `deploy/Containerfile`:
   - Install the extra packages with `--no-deps` and list their runtime deps explicitly:
     `soundfile safetensors python-multipart pydantic-settings python-dotenv` (soundfile bundles
     libsndfile; numpy/pydantic already come from the proven base). The import check stays and is
     the backstop if a dependency is missing.
   - Extend the stale-service guard to `qwen3|vllm serve|uvicorn` (and keep it failing the build).
   - Keep the ffmpeg/curl checks and `CMD []`.
2. `tests/test_deploy.py`:
   - Assert `--no-deps` is used for the extra-package install and that the engine stack
     (fastapi/uvicorn/httpx/numpy/pydantic) is not in that install list.
   - Assert the guard pattern includes `uvicorn`.
   - Replace the existence-only reference test with SHA-256 pins of `deploy/voxcpm2-3090.yaml` and
     `deploy/compose.yaml` (compute the current hashes; the test fails if either is edited).
