## Context

Startup review found: `/` has no cache headers (redirect loop), gate flips on a single health blip, `restart_in_s` is hard-coded null despite the documented 30/60/120 backoff, step 4 stays `done` after a post-warm engine loss, the failure timeout uses the app clock instead of the current attempt, a permanently failing warm-up never reaches `failed`, `reset()` mixes clocks, the log watermark mis-handles stale/truncated logs, snapshot/reset race without a lock, restart route has no lock and leaves state `starting` on failure, and warm-up requests pollute the RTF window although the UI says they are excluded.

## Steps

1. `app/startup.py`:
   - Two clocks: `_app_t0` (immutable, for `elapsed_s`) and `_attempt_t0` (set at start/reset and whenever a warm engine becomes unready). Step durations use `_attempt_t0`; `reset()` never changes `elapsed_s` semantics.
   - `ever_ready` flag; once warm, set it.
   - On `not warm` after step 4 was done: clear step 4, start a new attempt clock, log `[app] Engine not ready; re-warming`.
   - Failure timeout: `monotonic() - _attempt_t0 > settings.startup_fail_after_s` (only while engine not ready). If `engine.ready` but `warmup.last_error` after the attempt started, mark step 4 failed with that (plain) message.
   - `restart_in_s`: read `/run/engine-failures` (int) and `/run/engine-last-exit` (epoch seconds) in a try/except; `remaining = backoff[n] - (now - last_exit)` for n=1/2/3 where backoff=[None,30,60,120]; return max(0, ceil) or None for n=0/>3 or unreadable.
   - Log watermark: initialize `_scan_from` from the current file size; detect truncation/rotation by `(st_ino, st_size)` or by size < watermark and reset; on `reset()` reset the watermark.
   - A `threading.Lock` around `snapshot()` and `reset()`; derive `state` once.
   - Robust ANSI stripping (CSI with private modes + OSC), step 3 GPU detail without the `NVIDIA GeForce ` prefix.
2. `app/main.py`:
   - `/` responses get `Cache-Control: no-store`.
   - Gate only until the app has **ever** been ready: `settings.startup_page and not startup.ever_ready` → `/api/*` 503, except `/api/engine/startup` and `/api/engine/restart`; compare `path.rstrip("/")`. Body message distinguishes starting vs failed.
3. `app/warmup.py`: clear `warm` only after 3 consecutive health failures (counter reset on success); keep re-warm behavior.
4. `app/engine.py`: add `record: bool = True` to `synth()` and `open_stream()`; when false, do not append to the RTF/first-audio deques. `app/warmup.py` passes `record=False` for both warm-up requests. `app/speech.py` keeps the default (do not edit it).

   - `asyncio.Lock` around restart; set `warmup.warm=False` before `startup.reset()`.
   - On restart/warm-up failure, mark the tracker failed (step 3/4 + message) before returning the 503/502.
   - `engine.restart()` must clear `/run/service/engine/down`, `/run/engine-failures`, `/run/engine-last-exit` and run `s6-svc -u` before `s6-svc -r` (helps M2-T17's backoff).
6. ### Deviations

1. `WarmupService` gained a sticky `ever_warm` (set when a warm-up succeeds) and the tracker's
   `ever_ready` reads it. A flag set only inside `snapshot()` would keep the gate dependent on the
   page polling, so an API-only container could be re-gated by a blip.
2. The warm-up failure rule is `engine.ready and last_error not in (None, NOT_READY_ERROR)`
   rather than timestamping error changes. Timestamping misfired on the post-warm loss: the loss
   branch baselines the error it just observed and a permanently failing warm-up never reached
   `failed`. The sentinel is excluded because `run_forever` writes it while the engine is down —
   that path is owned by the attempt timeout.
3. Step durations are stored per step (`_durations`) instead of derived from completion
   timestamps, so a new attempt can never produce negative or app-age durations; `reset()` keeps
   step 1's duration and never touches `elapsed_s` semantics.
4. `restart_in_s` is only computed when the state is not `ready`: the s6 counters survive a
   recovery until a manual restart clears them, and a healthy app must not show a countdown.
5. `s6-svc -u`'s non-zero exit is ignored (already-up is not an error); a missing `s6-svc` still
   surfaces as the usual 502 from the `-r` call.
6. `tests/test_startup.py` fatal-line tests now create the tracker first and then append, which is
   what the new watermark semantics require (lines from a previous run are not this attempt's
   failure). A stale-log and a rotated-log (new inode) case cover both directions.
