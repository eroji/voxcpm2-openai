## Context

VoxCPM2 is a 30-language model and needs no language tag (the text determines the language).
vLLM-Omni's adapter has a generic internal `supported_languages` default (11) that is **not**
exposed over HTTP and is not VoxCPM2-specific. The authoritative list is the Hugging Face model
card: Arabic, Burmese, Chinese, Danish, Dutch, English, Finnish, French, German, Greek, Hebrew,
Hindi, Indonesian, Italian, Japanese, Khmer, Korean, Lao, Malay, Norwegian, Polish, Portuguese,
Russian, Spanish, Swahili, Swedish, Tagalog, Thai, Turkish, Vietnamese.

## Steps

1. `app/languages.py`: `LANGUAGES: tuple[dict[str,str], ...]` with ISO codes and English names in
   that order; `LANGUAGE_NAMES` dict; `language_name(code)` helper (falls back to the code).
   Codes: `ar my zh da nl en fi fr de el he hi id it ja km ko lo ms no pl pt ru es sw sv tl th tr vi`.
2. `app/routers/languages.py`: `GET /api/languages` → `{"languages":[{"code","name"}, ...]}`.
   No new auth logic (the `/api` middleware covers it).
3. `app/main.py`: include the router.
4. `tests/test_languages.py`: exactly 30 entries, unique, expected first/last codes, all names
   non-empty, route 200 + shape, and 401 when `studio_auth` is set without credentials (reuse the
   auth test pattern).
5. Update `docs/CONTRACTS.md` §2 with the route and the 30-language list; note that VoxCPM2 needs no
   request language tag (the selection only drives presets and metadata).
6. Do not edit UI or presets.
