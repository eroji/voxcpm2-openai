- **requirements:** R-010, R-011

## Context

SPEC §5 says import is lossless and `mime_type`, `original_filename`, `file_size` are carried over.
Wave-1 review proved `VoiceStore.create` overwrites `created_at` and `file_size`, and the importer
passes the lowercase key as the display `name`. The test's `file_size` assertion matched the
recomputed value, so it could not catch the loss. Also accept only float32 mono non-empty tensors.

## Steps

1. `app/store.py` — `create(...)`:
   - Use `meta.setdefault("created_at", str(now))` and
     `meta.setdefault("file_size", str(len(wav_bytes(...))))` **after** merging caller metadata, so
     imported values win.
   - Keep `name` as the passed display string; `voice_name_lower` stays the key.
   - Reject a non-1-D or empty audio array with `BadRequest` (`invalid_audio`) before writing.
2. `app/importer.py`:
   - Pass `name=meta.get("name") or key` (preserve display casing) to `store.create`.
   - Reject non-1-D/empty/corrupt tensors into `failed` with a short reason; never abort the batch.
   - Keep suffix→language and consent→source mapping.
3. Tests:
   - Rewrite the lossless assertion with non-derivable values: source metadata
     `file_size="12345"`, `created_at="1700000000"`, `name="Ashley-EN"`; import → stored metadata
     keeps exactly those values and `voice.name == "Ashley-EN"`, key `ashley-en`.
   - Add a stereo (2-D) source tensor and an empty tensor to the `failed` set; add a
     `voice_name_lower="../evil"` file → `failed`, no file written outside `voices/`.
   - Keep the skip/overwrite tests green.
4. Do not edit routers, fixtures or `app/audio.py`.

## Report

### Files changed

- `app/store.py` — `VoiceStore.create`: rejects non-1-D/empty audio with
  `BadRequest(code="invalid_audio", param="file")` before any write or backup; `created_at` and
  `file_size` are now `meta.setdefault(...)` **after** the caller-metadata merge, so imported values
  win and only new voices get the recomputed values. `name` stays the passed display string,
  `voice_name_lower` stays the validated key.
- `app/importer.py` — `key = meta.get("voice_name_lower") or path.stem`,
  `name = meta.get("name") or key` (display casing preserved into `store.create`). No tensor check
  duplicated here: `store.create` raises `BadRequest` and the existing per-file `except` routes it
  to `failed`, so the batch continues. Suffix→language and consent→source mapping untouched.
- `tests/test_store.py` — added `test_create_keeps_caller_metadata_and_defaults_the_rest`
  (caller `created_at`/`file_size`/`mime_type` win; plain create still gets
  `file_size == len(wav_bytes(...))` and a current `created_at`) and
  `test_create_rejects_non_1d_or_empty_audio` (stereo + empty → `invalid_audio`, nothing written).
- `tests/test_importer.py` — `speaker_file` gained `file_name=`/`name=`/`audio=` kwargs so a file's
  name and its declared key can differ and the tensor can be arbitrary. Added
  `test_import_is_lossless_for_values_code_cannot_derive` (`file_size="12345"`,
  `created_at="1700000000"`, `name="Ashley-EN"` → stored values identical, key `ashley-en`) and
  `test_bad_tensors_and_paths_fail_without_aborting` (stereo, empty, `voice_name_lower="../evil"` →
  all in `failed`, the 7 good voices still import, `data_dir.rglob("*evil*")` is empty). The old
  derivable-value assertion now checks `created_at == "1791831655"` instead of the recomputed
  `file_size`. Skip/overwrite tests unchanged and green.
