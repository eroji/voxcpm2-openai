- **Milestone:** M3
- **Wave:** 16

- **requirements:** SPEC v0.2.0 (§8 Design languages), R-039/R-040

## Context

`GET /api/languages` now returns the 30 VoxCPM2 model-card languages (`{code,name}`). The UI still
hardcodes en/ja/ko/zh in Clone, Design and `formatLang`, and native select chevrons sit against the
right border instead of aligning with the 8 px left text padding. VoxCPM2 needs no request language
tag, so the selection drives presets + stored metadata only.

## Steps

1. `app/static/studio.css`:
   - `.vs-select`: `appearance: none` (and `-webkit-appearance`), `background-color: var(--vs-bg)`,
     a small chevron SVG (`#EDEDED`) as `background-image`, `background-repeat: no-repeat`,
     `background-position: right var(--vs-s3) center`, `background-size: 10px 6px`, and
     `padding-right: calc(var(--vs-s3) + 16px)`. Keep the 8 px left padding so the chevron aligns
     with the text margin. This covers every dropdown (Speak format, Clone language, Design
     language/candidates).
2. `app/static/js/core.js`:
   - `state.languages = []`; `loadLanguages()` fetches `/api/languages` once and caches.
   - `formatLang(code)` uses the fetched map (fallback to the code); keep the four common names as
     a fallback before load.
   - Export `loadLanguages`.
3. `clone.js`: on `show/init`, populate `#clone-lang` from `state.languages` (English selected by
   default); preserve the current value when re-rendering.
4. `design.js`: populate `#design-lang` from `state.languages` (Japanese selected by default). For
   languages present in `presets.json` (en/ja/ko/zh) render the six chips as now; for any other
   language hide `#design-presets` and leave the textarea content alone (no fake translations),
   with a short hint (“No sample phrases for this language yet — type a line.”). Changing language
   re-renders; switching back to a preset language restores the chips without overwriting typed
   text unless a preset is selected.
5. `speak.js`: when the selected voice's language has no presets, hide the preset row (keep the
   text editable); for en/ja/ko/zh keep the current behavior. Update the language label from
   `formatLang`.
6. `voices.js`: no logic change beyond using `formatLang` for the table/filter labels (already
   does); ensure unknown codes render readably.
7. Tests:
   - `test_ui_assets.py`: `.vs-select` has `appearance:none`, chevron SVG, right `var(--vs-s3)`
     position and right padding; core exports `loadLanguages`; no hardcoded 4-language map remains
     (or it is documented as fallback).
   - e2e: Design language select has 30 options; selecting German hides the preset chips and keeps
     the text editable; selecting Japanese restores them. Clone select has 30 options. Pick a
     German voice? (not needed). Keep the existing preset tests green.
8. Do not edit Python or presets.

### Deviations

- Step 6 said "no logic change beyond `formatLang`" for `voices.js`, but the editor's hardcoded `LANGS` was a data-loss path once voices could carry other languages: `langSelect.value = "de"` matched no option, so the select displayed `en` and a plain Save silently rewrote the voice's language. Options now come from `state.languages`, with the voice's own code appended when absent. This is the smallest fix that keeps an unknown code readable and round-trippable.
- The Design hint element is created in JS and inserted after `#design-presets`, because `index.html` is outside `owns:` and has no spare node for it.
- Speak hides the whole labelled `.vs-row` (via `closest(".vs-row")`) rather than only the chip box, so the "Test phrases" label does not sit alone over an empty row.

### Open questions

- None blocking. `GET /api/languages` is assumed served by the M2-T19 router (present at `app/routers/languages.py` and wired in `app/main.py`); the e2e app exercises it through the real server, so a missing route would fail the 30-option tests rather than pass silently.
- `presets.json` still ships only `en/ja/ko/zh`. If translations for more of the 30 land later, no code change is needed — the chips appear automatically.
