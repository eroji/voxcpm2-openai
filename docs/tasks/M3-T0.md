## Context

Wave-1 review found four shell defects to fix before the screen modules are written:

1. `core.js` defers `start()` with `setTimeout(0)` when `readyState !== "loading"`, which can run
   before sibling screen modules register — the initial Speak `show()` never fires.
2. The header cannot render `Not ready · <reason>`; `EngineStatus.reason` now exists (lead change).
3. The clone drop-zone says "5–20 seconds"; SPEC §7/§8/§10 require 3–30 s.
4. The visually-hidden file input has no visible focus indication (`focus-within` missing).

## Steps

1. `core.js`:
   - Start on `DOMContentLoaded` when loading, else call `start()` directly (no `setTimeout`).
   - `refreshEngine()`: `ready` → `Ready · <gpu or model>`; not ready and `reason` →
     `Not ready · <reason>`; otherwise `Warming up…`. Text only, never color-only.
   - Keep the wavePath algorithm byte-identical to `ui/studio.html`.
2. `index.html`: clone copy "3–30 seconds of clean, single-speaker speech"; design language
   default matches the reference (Japanese first) or set an explicit default that matches §8 (the
   spec does not pin it — use the reference order).
3. `studio.css`: `.vs-drop:focus-within { outline: 2px solid var(--vs-accent); outline-offset: 2px; }`
   and ensure `[hidden]` still wins.
4. `tests/test_ui_assets.py`: add assertions for the three copy/rendering rules (string
   "3–30 seconds", `reason` used in core.js, focus-within rule), and a `node --check`-independent
   check that the start() handler uses `DOMContentLoaded`.
5. Do not edit screen modules or app Python code.
