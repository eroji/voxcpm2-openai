## Context

The updated SPEC removes the Qwen3 import entirely: no import-on-start, no `POST /api/voices/import`,
no `/import/qwen3-speakers` mount, and the acceptance wording no longer mentions imported voices.
Voices are created only via Clone/Design (or the API clone route).

## Steps

1. Delete `app/importer.py` and `tests/test_importer.py`.
2. `app/main.py`: remove the importer import and the import-on-start block.
3. `app/routers/studio_voices.py`: remove `POST /api/voices/import` (and its imports); the route
   must 404. Update `tests/test_studio_voices.py` accordingly (drop import tests, assert the route
   is gone and backups/CRUD still pass).
4. `deploy/compose.yaml`: remove the `/opt/qwen3-tts/data/speakers:/import/qwen3-speakers:ro`
   mount; update the SHA-256 pin in `tests/test_deploy.py` and any runbook-facing assumptions in
   that test.
5. `tests/test_acceptance.py`: replace the "import eight Qwen3 voices" test with one that creates
   eight voices through the real store (`store.create` for en/ja/ko/zh names) and synthesizes each
   over `/v1`; remove `settings.import_dir` usage. Keep the rest of the acceptance suite.
6. Search and remove remaining current-doc references to the importer in `docs/RUNBOOK.md`
   (import volume/steps) and `docs/CONTRACTS.md` (§1/§4 importer mentions). Historical briefs and
   PLAN rows stay, but mark R-011 as superseded in `docs/PLAN.md`.
7. Do not edit settings/conftest (M1-T18 owns the `import_dir` field removal) or UI.
