# M2-T13 — Deterministic acceptance burst + host RTF/queue evidence

- **Milestone:** M2
- **Wave:** 8
- **owns:** `tests/fake_engine.py`, `tests/test_acceptance.py`, `scripts/smoke.sh`, `docs/RUNBOOK.md`
- **deps:** M5-T2
- **verify:** `.venv/bin/python -m pytest tests/test_acceptance.py -q && bash -n scripts/smoke.sh`
- **requirements:** R-047, R-049

## Context

Release review: the acceptance 20-request burst relies on 20 threads reaching the app inside the
fake engine's fixed 250 ms `slow` window, so it can flake on a loaded runner; `X-RTF ≤ 0.2` is
asserted only against the fake engine (hardware criterion unverified); the runbook queue probe
ignores `API_KEYS`.

## Steps

1. `tests/fake_engine.py`: make the delay configurable via `FakeEngine.state["delay"]` (default
   0.25 s); accept `x_delay` in the request body as an optional override (fake only). Keep existing
   behaviour for other tests.
2. `tests/test_acceptance.py`:
   - Set `state["delay"] = 1.0` (or send `x_delay`) for the burst test so 20 requests reliably
     overlap; assert all statuses ∈ {200,429}, ≥18 200s, ≥1 429 with `Retry-After`, no 5xx.
   - Mark the fake-engine RTF assertion as a smoke check and add a `pytest.mark.skip` test
     `test_hardware_rtf_and_vram` naming the host blocker (Q-001/M0) so the §13 hardware bullet is
     visibly unproven rather than silently satisfied.
3. `scripts/smoke.sh`: assert the WAV response `X-RTF` is present and ≤ 0.2 on the real engine;
   make the queue probe use the same auth config as the other calls; add `-m` timeouts.
4. `docs/RUNBOOK.md`: acceptance section runs the host RTF/queue probe explicitly, notes the
   20-burst capacity (18 admitted, 2×429), and lists the remaining hardware checks.
5. Keep the skip list honest; do not add sleeps longer than needed.

## Definition of done

- [ ] `verify:` green, 3× with no flake; output in `## Report`.
- [ ] Burst is deterministic; hardware RTF is a named host check, not a fake-engine pass.
