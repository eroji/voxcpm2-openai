## Context

Reported bugs while testing:
1. Streamed playback is garbled (backend M1-T20 normalizes; the browser must also honour
   `X-Sample-Rate` instead of hard-coding 48 kHz).
2. Takes should highlight on hover/selection.
3. Play switches to pause while playing and animates through the clip.
4. The playing take's waveform lights up/animates with progress.
5. “Download” must look like “Save as voice” (not a blue underlined link).
6. Voice edit is cramped with a scrollbar; make it an inline full-width editor with name input,
   language select, auto-growing transcript, an Auto-transcribe overlay button, Edit→Save, then
   shrink the transcript to one line.
7. Clone copy: “Auto-transcribe with whisper-stt” → “Transcribe with STT”.
8. Tabs must not reflow when selected: remove the active `font-weight` change; only the 2 px accent
   underline indicates the current screen.
9. Takes are session-scoped: generate a per-page-load id in `core.js` (`crypto.randomUUID` with a
   hex fallback, shaped `[A-Za-z0-9_-]{1,64}`), send it as `X-Studio-Session` on every `api.*`
   request and on the raw `/api/speak` fetch; the list must start empty after a refresh (old takes
   stay on disk).

## Steps

1. `speak.js`:
   - `playPcmStream(res)`: read `X-Sample-Rate` from the response (fallback 48000) and use it for
     `AudioContext({sampleRate})` and `createBuffer(...)`; never hard-code 48 kHz.
   - Take player state: one active `Audio` element; clicking play toggles play/pause, swaps the play
     triangle for a pause icon (`<path d="M2 1h3v10H2zM7 1h3v10H7z"/>`), adds `.is-playing` to the
     row, and resets on ended/error. Playing another take stops the previous one.
   - Waveform: each row gets a grey base path plus an accent overlay path clipped by a `<rect>` in a
     `clipPath`; update the rect width from `audio.currentTime / duration` on `timeupdate` (and 0/full
     on start/end). The playing row's wave is the accent one; the newest-take idle accent rule
     remains.
   - Hover: CSS highlight (see step 4) on `.vs-take:hover`.
   - Download: keep `<a>` but style it like `.btn-link` (no browser blue/underline; inherit colour,
     underline on hover/focus only via the existing border).
2. `voices.js`: replace the per-cell editor with a full-width inline editor row (`<tr><td
   colspan="6">`):
   - grid with Name input, Language select (enabled languages + the voice's own code), and a
     Transcript `<textarea>` plus an “Auto-transcribe” button overlaid/next to it.
   - textarea auto-grows on input (reset height, set `scrollHeight`), no row scrollbar; row height
     expands.
   - The row's Edit button becomes **Save**; add Cancel. Save PATCHes changed fields; then re-render
     that row as a normal row with the transcript clamped to one line.
   - Auto-transcribe: fetch `/api/voices/{key}/audio`, send it as multipart `file` to
     `/api/transcribe`, fill the textarea (disable button while running; show 503 inline).
   - Keep focus management (focus Save/confirm) and in-flight guard.
3. `clone.js` + `index.html`: change the button copy to “Transcribe with STT” (and any aria label).
4. `studio.css`: tabs keep the same font weight when active (underline only);
   `.vs-take:hover, .vs-take.is-playing { background: var(--vs-code-bg); }` and an
   accent top rule for `.is-playing`; `.btn-link` (and `a.btn-link`) `color: inherit; text-decoration:
   none;`; voice editor grid/textarea styles; play button `.is-playing` state if needed.
5. Tests:
   - `test_ui_assets.py`: clone copy, `X-Sample-Rate` use, play/pause icon path, clipPath progress,
     editor `colspan`, textarea auto-grow hook, btn-link colour rule.
   - e2e: generate a take; click play → button aria-label/title becomes Pause, row has
     `.is-playing`, accent clip width grows (>0) after ~0.3 s, click again pauses; hover adds the
     class/CSS; Download computed color matches Save as voice and has no underline; edit a voice:
     editor spans the row (no horizontal scroll), transcript grows, Auto-transcribe button exists,
     Save collapses it to one line; clone shows “Transcribe with STT”.
6. Do not edit Python or language modules.

**Deviations:**

1. `core.play(url)` gained an **optional** second argument and `setWaveProgress` was added — both
   additive to CONTRACTS §7 (every existing one-arg caller is unchanged). Owning the player in core
   keeps the brief's "one active `Audio` element" true across screens: auditioning a voice stops a
   take and vice versa, which a second element inside `speak.js` could not do.
2. Focus: opening the editor focuses the **Name** field (so typing works immediately); the delete
   confirm still focuses Delete. The brief's "(focus Save/confirm)" is read as "keep focus on the
   actionable control", which the previous code did the same way.
3. `if (stream) body.sample_rate = 48000;` is kept on the request (it avoids a server-side resample
   pipe); the **decoder** now follows `X-Sample-Rate`, with 48000 only as the fallback.
4. Clone copy: SPEC §8 still prints "Auto-transcribe with whisper-stt"; this brief mandates
   "Transcribe with STT", so the UI now differs from the spec text.
