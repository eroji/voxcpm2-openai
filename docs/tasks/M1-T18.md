## Context

Updated SPEC:
- Warm-up requests **and any request that started before `/ready` went green** must be excluded
  from RTF/first-audio metrics.
- With an empty library, `/api/speak` and `/v1/audio/speech` return 400
  `{"error": {"code": "no_voices", "message": "No voices exist yet. Create one in the Studio (Clone or Design) first."}}`.
  Ad-hoc `ref_audio` previews still work without a stored voice.
- `/v1` must be 503 until warm (`/ready` 200).

## Steps

1. `app/config.py`: remove the now-unused `import_dir` field (M2-T18 removes the importer).
   `tests/conftest.py`: remove `import_dir=` and make the `client` fixture wait for `/ready` 200
   (poll ≤ 5 s; if the app's engine is intentionally dead, skip the wait) so warm-only routing does
   not break the suite.
2. `app/speech.py`:
   - `resolve()`: when no `ref_audio` and `store.list()` is empty → `BadRequest` with the exact
     `no_voices` message/code above.
   - Keep ad-hoc `ref_audio` working with an empty store.
   - Synthesis records metrics only when the request starts warm: add an optional
     `record: bool = True` to `SpeechService.synthesize`/`stream`, forwarded to
     `engine.synth`/`open_stream`; routers pass `record=request.app.state.warmup.warm`. (Warm-up
     already passes `record=False`.)
3. `app/routers/v1.py` and `app/routers/studio_takes.py`: before resolving/synthesizing, require
   `request.app.state.warmup.warm`, else raise `EngineNotReady` (503 + Retry-After 5). This closes the
   pre-ready window so metrics never include those requests. `/api/speak?save=false` is also warm-only.
4. `tests/test_metrics.py` (new): with `record=False`, engine metric deques do not change; with
   `record=True` they do. Use `EngineClient` directly with `fake_engine` (synth + open_stream).
5. Tests:
   - Empty library (`client` with no `library`): `/v1/audio/speech` WAV → 400 `no_voices` exact
     message; `/api/speak` → same; `/api/speak?save=false` with `ref_audio` still 200; `/v1` with
     `ref_audio` still 200.
   - Non-warm app: build `create_app(Settings(..., startup_page=False))` with a stub `/ready` 503
     (e.g. warmup not run) → `/v1/audio/speech` and `/api/speak` 503 + Retry-After.
   - Existing tests stay green (update expected errors where the empty message changed).
6. Do not edit `app/startup.py`, `app/main.py`, UI, or store.

### Out-of-`owns:` breakage caused by the `import_dir` removal

`tests/test_auth.py:17` still reads `settings.import_dir` inside `_settings()`, so 4 tests fail
with `AttributeError: 'Settings' object has no attribute 'import_dir'`:
`test_studio_auth_gates_ui_api_static`, `test_api_keys_gate_covers_v1_voices`,
`test_malformed_auth_config_fails_startup`, `test_non_ascii_basic_credentials_never_500`.
`tests/test_config.py:15`, `tests/test_studio_engine.py:52` and `tests/e2e/conftest.py:62` only
*pass* `import_dir=` as a kwarg, which `extra="ignore"` swallows — those suites are green.
Fix is deleting that one line; `tests/test_auth.py` is in nobody's `owns:` this wave, so I did not
touch it. **BLOCKED: needs tests/test_auth.py (unowned in wave 14)** for that one line only.

### Deviations

1. The empty-library check sits in `resolve()`'s existing `except APIError` branch (after
   `store.get` fails) instead of an unconditional `store.list()` before the lookup. Same behaviour
   — an empty store always fails the lookup — without an extra metadata read on every request.
2. The `no_voices` body leaves `param` null (SPEC §8 quotes only `code` and `message`).
3. `tests/test_v1.py`'s upstream-429/503 tests now stub `WarmupService.run` to succeed
   (`_force_warm`): those stub engines fail every synthesis, so the warm gate would answer 503
   before the upstream status mapping under test could run. Setting `warmup.warm = True` directly
   was racy — the in-flight real warm-up clears it again.
